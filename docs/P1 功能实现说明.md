## 一、已实现的功能

### 1. 多因子认证（MFA）

#### 1.1 核心功能
- ✅ TOTP（基于时间的一次性密码）生成和验证
- ✅ 支持 Google Authenticator 等认证器应用
- ✅ MFA 启用、验证、禁用完整流程
- ✅ QR 码 URI 生成（可配合二维码生成库使用）

#### 1.2 技术实现
- **依赖库：** `fast-otp` (com.eatthepath:fast-otp:3.0.1)
- **算法：** HMAC-SHA256
- **密码长度：** 6 位数字
- **有效期：** 30 秒

#### 1.3 API 接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 初始化 MFA | POST | `/api/mfa/setup` | 生成 MFA 密钥和 URI |
| 验证并启用 | POST | `/api/mfa/setup/verify` | 验证 TOTP 并启用 MFA |
| 验证 TOTP | POST | `/api/mfa/verify` | 验证一次性密码 |
| 禁用 MFA | POST | `/api/mfa/disable` | 禁用 MFA 功能 |
| 查询状态 | GET | `/api/mfa/status` | 查询 MFA 启用状态 |

#### 1.4 使用流程

**步骤 1：初始化 MFA**
```bash
POST /api/mfa/setup
Authorization: Bearer <token>

Response:
{
  "code": 200,
  "message": "MFA 初始化成功",
  "data": {
    "secret": "JBSWY3DPEHPK3PXP...",
    "qrCodeUri": "otpauth://totp/CaSystem:user@example.com?secret=...",
    "manualEntryKey": "JBSWY3DPEHPK3PXP"
  }
}
```

**步骤 2：使用认证器扫描二维码**
- 使用 Google Authenticator、Microsoft Authenticator 等应用扫描二维码
- 或手动输入 `manualEntryKey`

**步骤 3：验证并启用**
```bash
POST /api/mfa/setup/verify
Authorization: Bearer <token>
Content-Type: application/json

{
  "code": "123456"
}
```

**步骤 4：后续登录验证**
- 在关键操作前调用 `/api/mfa/verify` 验证 TOTP

#### 1.5 数据库变更
```sql
ALTER TABLE users 
ADD COLUMN mfa_enabled TINYINT(1) DEFAULT 0,
ADD COLUMN mfa_secret VARCHAR(512) DEFAULT NULL,
ADD COLUMN mfa_verified TINYINT(1) DEFAULT 0;
```

### 2. 证书到期提醒

#### 2.1 核心功能
- ✅ 定时任务自动检查即将到期的证书
- ✅ 支持多时间点提醒（30 天、15 天、7 天）
- ✅ HTML 格式邮件模板
- ✅ 可配置提醒策略

#### 2.2 技术实现
- **定时任务：** Spring Scheduler
- **邮件发送：** Spring Boot Mail
- **执行时间：** 每天早上 9:00

#### 2.3 配置项

在 `application.yml` 中配置：
```yaml
app:
  mail:
    enabled: true  # 启用邮件服务
    from: noreply@casystem.com
    smtp-host: smtp.qq.com
    smtp-port: 587
    username: your-email@qq.com
    password: your-auth-code
  
  reminder:
    days-before-expiry: 30,15,7  # 提醒天数
```

#### 2.4 邮件内容
- 证书序列号
- 组织名称
- 有效期
- 剩余天数（颜色区分紧急程度）
- 温馨提示

#### 2.5 手动触发
```bash
# 调用服务方法
certificateReminderService.sendManualReminderEmail("证书序列号");
```

### 3. 证书验证工具

#### 3.1 核心功能
- ✅ 证书解析（X.509 格式）
- ✅ 证书链验证
- ✅ 证书状态检查
- ✅ 扩展字段解析

#### 3.2 API 接口

| 接口 | 方法 | 路径 | 说明 |
|------|------|------|------|
| 证书解析 | POST | `/api/tools/parse` | 解析证书详细信息 |
| 证书链验证 | POST | `/api/tools/verify-chain` | 验证证书链完整性 |
| 状态检查 | POST | `/api/tools/check-status` | 检查证书有效期状态 |

#### 3.3 使用示例

**解析证书：**
```bash
POST /api/tools/parse
Content-Type: multipart/form-data

file: certificate.cer

Response:
{
  "code": 200,
  "message": "证书解析成功",
  "data": {
    "subject": "CN=example.com,O=Example Inc",
    "issuer": "CN=CA System,O=CA",
    "serialNumber": "1A2B3C4D5E6F",
    "notBefore": "2024-01-01T00:00:00Z",
    "notAfter": "2025-01-01T00:00:00Z",
    "signatureAlgorithm": "SHA256withRSA",
    "version": 3,
    "publicKeyAlgorithm": "RSA",
    "publicKeySize": 2048,
    "fingerprint": "A1:B2:C3:...",
    "extensions": [...]
  }
}
```

**验证证书链：**
```bash
POST /api/tools/verify-chain
Content-Type: multipart/form-data

cert: server.crt
chain: intermediate.crt
chain: root.crt
```

#### 3.4 解析内容
- 主题（Subject）
- 颁发者（Issuer）
- 序列号
- 有效期
- 签名算法
- 公钥信息
- 指纹（SHA-256）
- 扩展字段：
  - 基本约束
  - 密钥用途
  - 增强密钥用途
  - 主题备用名称

## 四、注意事项

### 1. MFA 相关
- MFA 密钥需要安全存储，建议加密
- 生产环境应使用 HTTPS
- 建议提供 MFA 备用码功能

### 2. 邮件服务
- 使用授权码而非密码（QQ 邮箱等）
- 建议配置 SSL/TLS 加密
- 注意邮件发送频率限制

### 3. 证书验证
- 大文件上传需要配置 max-file-size
- 证书链验证需要完整的中间证书

### 4. 审计日志
- 定期清理旧日志（建议保留 6 个月）
- 敏感信息需要脱敏
