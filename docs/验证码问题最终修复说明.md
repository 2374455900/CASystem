# 验证码问题最终修复说明

**修复日期：** 2026-04-13  
**问题：** 申请证书时提示"验证码不能为空"  
**状态：** ✅ 已修复

---

## 🎯 根本原因

**CaptchaController 生成验证码后，没有将验证码存储到 Session 中！**

前端虽然获取到了验证码图片，但后端 Session 中没有存储验证码，导致验证时 `sessionCode` 为 `null`。

---

## ✅ 最终修复方案

### 修复 1：CaptchaController 添加 Session 存储

**文件：** `backend/src/main/java/com/kuugae/ca/controller/CaptchaController.java`

**修改内容：**

1. 添加 HttpSession 注入：
```java
@Slf4j
@RestController
@RequestMapping("/api/captcha")
@RequiredArgsConstructor
public class CaptchaController {
    private static final String SESSION_KEY = "checkCode_session";
    private final HttpSession httpSession;
```

2. 在 generateCaptcha 方法中存储验证码到 Session：
```java
@GetMapping("/generate")
public ResponseEntity<ApiResponse<Map<String, Object>>> generateCaptcha() throws IOException {
    String captchaCode = generateCode();
    BufferedImage image = generateImage(captchaCode);

    // 将验证码存储到 Session
    if (httpSession != null) {
        httpSession.setAttribute(SESSION_KEY, captchaCode);
        log.debug("验证码已存储到 Session: {}", httpSession.getId());
    } else {
        log.warn("HttpSession 为 null，无法存储验证码");
    }

    // ... 生成图片 ...
    return ResponseEntity.ok(ApiResponse.success(data));
}
```

### 修复 2：SecurityConfig 允许创建 Session

**文件：** `backend/src/main/java/com/kuugae/ca/config/SecurityConfig.java`

```java
.sessionManagement(session -> session
    .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED)
    .maximumSessions(1)
    .maxSessionsPreventsLogin(false)
)
```

### 修复 3：CertificateController 正确获取 Session

**文件：** `backend/src/main/java/com/kuugae/ca/controller/CertificateController.java`

```java
private final HttpSession httpSession;

private Object getSessionAttribute(String key) {
    if (httpSession != null) {
        return httpSession.getAttribute(key);
    }
    return null;
}

private void removeSessionAttribute(String key) {
    if (httpSession != null) {
        httpSession.removeAttribute(key);
    }
}
```

## 🔄 完整工作流程

### 正确的验证码流程

```
1. 前端访问 /apply 页面
   ↓
2. 前端调用 GET /api/captcha/generate
   ↓
3. CaptchaController:
   - 生成验证码 "ABCD"
   - 存储到 Session: session.setAttribute("checkCode_session", "ABCD")
   - 返回验证码图片
   ↓
4. 前端显示验证码图片
   ↓
5. 用户填写表单，输入验证码 "ABCD"
   ↓
6. 前端调用 POST /api/certificates/apply
   Body: { "checkCode": "ABCD", ... }
   ↓
7. CertificateController:
   - 从 Session 获取：sessionCode = session.getAttribute("checkCode_session")
   - 调用 ValidationService.validateCaptcha("ABCD", "ABCD")
   ↓
8. 验证通过：
   - 清除 Session 中的验证码
   - 处理证书申请
   ↓
9. 返回成功响应
```

## 📊 问题排查

### 问题 1：验证码图片无法显示

**可能原因：**
- 前端 API 调用失败
- 后端返回错误

**排查方法：**
1. 打开浏览器开发者工具
2. 查看 Network 标签
3. 检查 `/api/captcha/generate` 请求
4. 查看响应状态码和数据

### 问题 2：验证码验证失败

**可能原因：**
1. Session 未正确创建
2. Cookie 未传递
3. 验证码已过期

**排查方法：**
1. 检查后端日志
2. 查看 Session ID 是否一致
3. 确认 CORS 配置正确

### 问题 3：Session ID 不一致

**症状：**
- 生成验证码时 Session ID: ABC123
- 提交申请时 Session ID: XYZ789

**原因：**
- Cookie 未正确传递
- 跨域配置问题

**解决方法：**
1. 检查前端 `withCredentials: true`
2. 检查后端 CORS 配置
3. 确认 `setAllowedOriginPatterns` 包含前端地址

## 🔐 安全性

### 已实现的安全措施

✅ **验证码存储在服务端**
- 客户端无法直接获取验证码
- 只能看到验证码图片

✅ **验证码使用后立即清除**
- 防止重放攻击
- 每次申请都需要新验证码

✅ **Session 管理**
- 每个用户最多 1 个 Session
- Session 超时时间：30 分钟

✅ **日志记录**
- 记录验证码生成和验证
- 便于审计和排查问题

## 📝 注意事项

### 1. 开发环境 vs 生产环境

**开发环境：**
- Session 存储在内存
- 重启后 Session 丢失

**生产环境：**
- 建议使用 Redis 存储 Session
- 配置 Session 集群共享

### 2. 并发问题

- 每次请求验证码会覆盖之前的验证码
- 用户只能使用最新生成的验证码

### 3. Session 超时

- 默认 30 分钟无活动后超时
- 超时后需要重新生成验证码
