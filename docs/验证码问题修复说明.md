# 验证码问题修复说明

**修复日期：** 2026-04-13  
**问题：** 申请证书时提示"验证码不能为空"

---

## 🐛 问题原因

### 1. 后端 Session 未正确配置
- **SecurityConfig** 中设置了 `SessionCreationPolicy.STATELESS`
- 导致 HttpSession 无法创建，验证码无法存储到 Session

### 2. Controller 方法实现错误
- `CertificateController.getSessionAttribute()` 方法返回空 HashMap
- 无法从 Session 中获取验证码

---

## ✅ 修复方案

### 修复 1：修改 SecurityConfig

**文件：** `backend/src/main/java/com/kuugae/ca/config/SecurityConfig.java`

**修改内容：**
```java
// 修改前
.sessionManagement(session -> session
    .sessionCreationPolicy(SessionCreationPolicy.STATELESS)
)

// 修改后
.sessionManagement(session -> session
    .sessionCreationPolicy(SessionCreationPolicy.IF_REQUIRED)
    .maximumSessions(1)
    .maxSessionsPreventsLogin(false)
)
```

**说明：**
- `IF_REQUIRED`：按需创建 Session
- `maximumSessions(1)`：每个用户最多 1 个 Session
- `maxSessionsPreventsLogin(false)`：达到最大 Session 数时，允许新登录（使旧 Session 失效）

### 修复 2：修复 CertificateController

**文件：** `backend/src/main/java/com/kuugae/ca/controller/CertificateController.java`

**修改内容：**

1. 添加 HttpSession 注入：
```java
private final HttpSession httpSession;
```

2. 修复 getSessionAttribute 方法：
```java
// 修改前
private Object getSessionAttribute(String key) {
    return new HashMap<>().get(key);
}

// 修改后
private Object getSessionAttribute(String key) {
    if (httpSession != null) {
        return httpSession.getAttribute(key);
    }
    return null;
}
```

3. 修复 removeSessionAttribute 方法：
```java
// 修改前
private void removeSessionAttribute(String key) {
}

// 修改后
private void removeSessionAttribute(String key) {
    if (httpSession != null) {
        httpSession.removeAttribute(key);
    }
}
```

### 正确的验证码验证流程

   ```
   GET /api/captcha/generate
   ```

2. **后端生成验证码并存储到 Session**

3. **前端显示验证码图片**
   - 用户看到验证码图片

4. **前端提交证书申请**
   ```
   POST /api/certificates/apply
   Body: {
     "organization": "...",
     "checkCode": "1234"  // 用户输入的验证码
   }
   ```

5. **后端验证验证码**
   ```java
   // CertificateController
   String sessionCode = getSessionAttribute("checkCode_session");
   // 从 Session 中获取之前生成的验证码
   ValidationService.validateCaptcha(inputCode, sessionCode);
   ```

6. **验证通过后清除 Session 中的验证码**
   ```java
   removeSessionAttribute("checkCode_session");
   ```

## 📝 注意事项

### 1. Session 超时
- 默认 Session 超时时间：30 分钟
- 验证码有效期：Session 生命周期内
- 建议：前端定期刷新验证码（如 5 分钟）

### 2. 跨域问题
- 已配置 CORS 允许携带凭证
- 前端已设置 `withCredentials: true`
- 确保前后端同源或 CORS 配置正确

### 3. 并发问题
- 每个 Session 只能存储一个验证码
- 每次请求验证码会覆盖之前的验证码
- 验证码使用后立即清除

### 4. 安全性
- ✅ 验证码存储在服务端 Session
- ✅ 客户端无法直接获取验证码
- ✅ 验证码使用后立即失效
- ✅ 防止重放攻击

## 🔍 调试技巧

### 查看 Session 状态

**后端日志：**
```java
log.info("Session ID: {}", httpSession.getId());
log.info("Session 中的验证码：{}", httpSession.getAttribute("checkCode_session"));
```

**浏览器开发者工具：**
1. 打开 Network 标签
2. 查看请求的 Cookie 头
3. 确认 JSESSIONID 是否正确传递

### 常见问题排查

**问题 1：验证码一直刷新**
- 原因：每次请求都生成新验证码
- 解决：确保验证码只在需要时生成

**问题 2：Session ID 不一致**
- 原因：Cookie 未正确传递
- 解决：检查 CORS 和 withCredentials 配置

**问题 3：验证码验证失败**
- 原因 1：Session 超时
- 原因 2：验证码已被使用
- 原因 3：前后端字段名不匹配
- 解决：检查日志，确认 Session 中的验证码值
